## wmux-agent-skill-suite v0.0.1

首次發布。兩個 coding-agent 中立、以 `SKILL.md` 格式撰寫的技能：`wmux-best-practice`（wmux pane 操作 primitive）與 `wmux-coordinator`（跨 pane 派工協調，依賴前者）。

### 技能來源與重新命名

從 [maze-coder](https://github.com/bext1998/maze-coder) 依 [Issue #31](https://github.com/bext1998/maze-coder/issues/31) 遷移而來：

| 舊名稱（maze-coder） | 新名稱（本 repo） |
|---|---|
| `extensions/wmux`（技能 `wmux`） | `skills/wmux-best-practice` |
| `extensions/wmux-orchestrator`（技能 `wmux-orchestrator`） | `skills/wmux-coordinator` |

遷移只調整 frontmatter、標題、描述、路徑引用與內部名稱引用，**未縮減任何觸發情境、操作能力、安全邊界、狀態模型、Worker Registry 或 per-harness 適配層**。`wmux-coordinator` 對 `wmux-best-practice` 的引用改為相對路徑，兩個技能仍需同層安裝。

maze-coder 端已對應移除原本的兩個 extension 技能與安裝說明，不保留同步副本、submodule 或執行期相依。

### wmux 驗證版本

以 wmux `v0.38.0` 作為本次發布的適配與驗證基準：

- Annotated tag SHA：`60dd5e51e1ccf269b3d59290f33b985a79763837`
- Commit：`7882751c57da360635d22c36ff13f6294af27796`
- 平台：`win32`
- Capabilities：`protocols: ["v1","v2"]`，`features: ["workspaces","splits","notifications"]`

建立本 repository 時的 upstream 最新正式版本是 `v0.41.0`，但使用者實際使用後回報該版本有嚴重效能問題，因此改採前一個確認可正常使用的版本 `v0.38.0` 作為基準；`v0.41.0` 僅作為已知限制記錄（見下方），不作為驗證基準。發布前重新確認 upstream 截至 2026-08-02 仍未發布比 `v0.41.0` 更新的正式版本。

### 安裝方式

兩個技能必須同時安裝、放在同一層目錄：

```bash
bash scripts/install.sh ~/.claude/skills   # 或任何其他目標技能目錄
```

支援任何解析 `SKILL.md` 格式的 coding agent（Claude Code、Codex、OpenCode、Pi 等）；各工具安裝路徑範例、環境需求（GNU coreutils `realpath`）與 Windows drive-letter/大小寫處理細節見 [docs/install.md](../install.md)。從舊名稱（`wmux`／`wmux-orchestrator`）遷移的說明見 [docs/migration.md](../migration.md)——**不得同時安裝新舊名稱**。

### 已知限制

- **wmux v0.41.0 有嚴重效能問題**（使用者實際使用回報），本次發布未採用，不對其效能問題的量測數據或根因做任何未經查證的推測。
- **v0.41.0 新增的 agent-state／`answer-agent` 指令家族在 v0.38.0 上不存在**，本次發布的兩個技能皆未採用、未實測。這組指令理論上可以讓 orchestrator 不必切換 pane 就能回覆 `blocked` 的 agent，但 upstream 官方文件明確聲明 **Claude Code 目前無法宣告結構化選項（`--choices`）**，即使未來改用 v0.41.0，對 Claude Code worker 而言也不會有實際差異。
- 本次發布的行為結論實機驗證平台僅限 **Windows（`win32`）**；macOS/Linux 尚未實測，行為可能不同，使用前建議先以 `identify`/`capabilities` 核對。
- `wmux-coordinator` 的 per-harness 適配層目前只對 Codex、Pi 做過完整即時互動實測；其他 harness（OpenCode 等）套用前需自行依技能文件描述的方法重新驗證。
- `scripts/install.sh` 的路徑安全檢查（symlink 解析、drive-letter/大小寫正規化）已對 Windows/Git Bash（MSYS）環境做過本機實測與負向測試；非 MSYS（Linux/macOS）平台的對應反向測試（驗證這些 Windows 專屬防護不會誤傷）僅在本次發布前透過程式碼審查與語法檢查確認，實際執行結果以 CI 的 `ubuntu-latest` runner 為準。
