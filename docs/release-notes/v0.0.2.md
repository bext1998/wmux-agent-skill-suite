## wmux-agent-skill-suite v0.0.2

延續 [Issue #8](https://github.com/bext1998/wmux-agent-skill-suite/issues/8) 的 wmux v0.42.0 相容性工作：完成剩餘的實機驗證，並依使用者反饋精簡兩個技能檔案的內容存放方式。

### wmux 驗證版本

整體驗證基準由 `v0.38.0` 正式升級為 **`v0.42.0`**：

- Annotated tag SHA：`a3f39aac07aae20f9f69b4354cfbc0766b86ba7f`
- Commit：`64b2db877dd8ddfd3ad965c5fc9db2d3bec92dbf`
- 平台：`win32`
- Capabilities：`protocols: ["v1","v2"]`，`features: ["workspaces","splits","notifications"]`（與 `v0.38.0` 一致）

2026-08-04／08-05（Windows win32）完成「執行前的授權邊界」四類操作在 `v0.42.0` 上的逐項重新驗證：

- **可逆寫入**（`send`/`send-key`/`notify`）：確認生效（以寫入磁碟檔案的副作用驗證，非只看 `ok:true`）
- **建立資源**（`split`/`new-surface`/`agent spawn`）：`split`/`new-surface --pane` 無效的既有結論重新確認；新發現 `agent spawn --pane` 可靠
- **破壞性**（`pane close`/`close-surface`/`agent kill`）：確認可靠；`close-pane --surface` 無效的既有結論重新確認
- **多視窗**（`new-window`）：首次在真實多視窗環境下驗證 `WMUX_SURFACE_ID` 的 caller 語意

Diff Pane、wmux 異常退出後的殘留程序清理，判定屬於 wmux app 本身（Electron main process／renderer）行為，不是本技能操作的 pane primitive，明確排除在技能範圍外，本次未測試、也不需要測試。

### 文件精簡

技能檔案不再逐版列出「版本重新驗證紀錄」段落（怎麼測的、哪天測的、用了哪些 ID）——這類過程紀錄一律移到 [CHANGELOG.md](../../CHANGELOG.md)，`SKILL.md` 本體只保留**目前**驗證基準與目前仍然成立的行為結論，降低技能檔案膨脹、方便 agent 執行任務時快速抓到當下該怎麼做。對應更新 `docs/skill-authoring-rules.md`、`CLAUDE.md`、`AGENTS.md` 反映這個慣例；規則本身不縮減既有行為結論，只搬動過程記錄的存放位置。

### 安裝方式

與 v0.0.1 相同，兩個技能仍需同時安裝、放在同一層目錄，見 [docs/install.md](../install.md)：

```bash
bash scripts/install.sh ~/.claude/skills   # 或任何其他目標技能目錄
```

### 已知限制

- `WMUX_SURFACE_ID` 的多視窗 caller 語意僅在乾淨雙視窗情境下驗證過；upstream 同日發布的 `v0.43.0`（[PR #144](https://github.com/amirlehmam/wmux/pull/144)）記載了「新視窗複製到重複 surface id」的 edge case 修正，本次未涵蓋、未實機驗證。
- 同一份 `v0.43.0` release notes 提到未知旗標行為將從「靜默忽略」改成「直接拒絕」，可能影響本技能記錄的 `split`/`new-surface --pane`（現況：靜默忽略）與 `close-pane --surface`（現況：`ok:true` 無效）行為；純文件調查，未實機驗證，升級到 `v0.43.0` 後應優先重測。
- `read-screen` 對非呼叫者自身 surface 的空讀比例，本次小樣本觀察比既有「間歇性空讀」描述更頻繁；`wmux-coordinator` 派工輪詢流程需更依賴既有的「空讀先重讀」處理。
- `clear-notifications` 疑似不生效（`ok:true` 但通知未被清除），與 v0.0.1 已知的 `ok:true` 不保證成功結論一致，非新增限制。
- 其餘既有限制（wmux v0.41.0 效能問題、`agent-state`/`answer-agent` 指令家族不採用、僅 Windows `win32` 實機驗證等）詳見 [v0.0.1 release notes](v0.0.1.md#已知限制)，本次未變更。
